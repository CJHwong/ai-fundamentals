# 1.3 天花板在哪裡

## LLM 不是什麼都行

理解 LLM 為什麼強之後，接下來要理解它為什麼會失敗。不是要潑冷水，是因為知道天花板在哪，你才知道怎麼設計有效的解決方案。

每個限制背後都有原因，而且不是「AI 還不夠聰明」這麼簡單。

## 四個根本限制

### 1. 沒有世界模型 (No World Model)

LLM 學到的是文字之間的統計關係，不是對世界的真正理解。

它知道「水在 100°C 會沸騰」，是因為這句話在訓練資料中出現過很多次，不是因為它理解什麼是水、什麼是溫度、什麼是沸騰。

這就是 **hallucination（幻覺）** 的根源。當 LLM 遇到訓練資料中沒有足夠 pattern 的問題，它不會說「我不知道」。它會生成一個統計上看起來合理、但事實上錯誤的答案。因為它的目標是「產出最可能的下一個字」，不是「產出正確的答案」。

> 實際案例：有一個負責處理 email 的 Agent，要依序呼叫四個工具。但它沒有等第一步的結果回來，就直接編造了後面三步的參數。訂單編號是假的，負責人的名字也不存在。它不是故意亂寫，它是在預測「最可能的參數值」。

**在改善嗎？** 是。更大的模型、更好的 reasoning 訓練（如 Chain-of-Thought）正在提升推理能力。但骨子裡它仍然是 pattern matching，不是 logical reasoning。

#### 試試看

請 AI 回答一個不存在但聽起來很合理的問題：

> 幫我摘要這篇論文的重點：「Beyond Attention: A Unified Framework for Post-Transformer Architectures」by Yann LeCun et al., 2025

這篇論文不存在。但作者名字是真的、主題是合理的、年份也說得通。看看 AI 會不會很有自信地「摘要」一篇根本不存在的論文。它不會說「我找不到」，因為它的目標是產出最可能的下一個字，不是產出正確的答案。

### 2. 有限的 Context Window

LLM 一次能「看到」的文字量是有限的，這就是 context window。超出這個範圍的資訊，它就是看不到。

而且 context window 不只是大小的問題。就算在 window 之內，資訊太多、太雜，模型的注意力也會被稀釋。

還記得 1.1 的 Attention 練習嗎？再加一個情境：

> 你的腳受傷了，必須去開會。你手邊有：一袋垃圾、一份過期報紙、一支拐杖。

你還是會選拐杖。但那些垃圾和報紙消耗了你的注意力，即使它們沒用。這就是 **noise**。

再換一個：

> 你手邊有：一把雨傘、一支掃把、一支登山杖、一支拐杖。

這四個東西長得像、功能有重疊。你開始猶豫了。這就是 **ambiguity**。

對 LLM 來說，noise 浪費算力但通常不致命，ambiguity 才是真正讓它出錯的原因。

**有在進步嗎？** Context window 從 GPT-3.5 的 4K tokens 到現在動輒 128K-1M tokens。但 window 變大不代表理解變好，noise 和 ambiguity 的問題還是在。

### 3. 沒有持久記憶 (No Persistent Memory)

每次對話，LLM 都是從零開始。它不記得昨天跟你聊了什麼、上週做了什麼決定、你的偏好是什麼。

它唯一的「記憶」就是當前 context window 裡的內容。對話結束，一切歸零。

這代表：
- 它無法從過去的錯誤中學習
- 它無法追蹤長期的專案進度
- 每次互動都要重新提供背景資訊

**有解嗎？** 各家都在做 memory 功能（ChatGPT 的 memory、Claude 的 project knowledge），但目前都是外掛的，模型本身還是不會記。

### 4. 無法自我驗證 (No Self-Verification)

LLM 沒有辦法確認自己的輸出是否正確。它生成一個答案之後，無法回頭檢查這個答案是否符合事實、是否邏輯一致、是否真的能執行。

它就像一個永遠自信滿滿的人，即使說錯了也不會臉紅。

**天花板在移動嗎？** 有，但有限。Reasoning model（如 o3）會在內部做更多推理步驟，但它終究無法自己去外部系統查證事實。

#### 試試看

讓 AI 數字數，不要讓它用工具：

> 請直接回答，不要寫程式：「strawberry」這個字裡面有幾個 r？「accummmodation」裡有幾個 m？

然後再試一次，但這次說：

> 請寫一段 Python 程式來數上面兩個問題的答案

比較兩次的結果。LLM 處理文字的單位是 token（詞的片段），不是字母，所以「數某個字母出現幾次」這種事對它來說出乎意料地困難。但用 tool（程式碼）就能精準回答。這就是「無法自我驗證」和「tool use 如何解決它」的對比。

## 一張表看限制與趨勢

| 限制 | 根本原因 | 目前的緩解方向 |
|------|---------|--------------|
| Hallucination | 統計預測，非事實推理 | 更強的 reasoning 訓練、RAG |
| Context 有限 | 固定的 window + attention 稀釋 | 更大的 window、更好的 context 管理 |
| 沒有記憶 | 每次推理獨立，無狀態 | 外掛 memory 系統 |
| 無法驗證 | 不能存取外部系統 | Tool use、code execution |

注意最右邊那一欄。Agent 的出現，就是為了補上 LLM 單獨運作時的這些不足。下一個 Part 我們就來聊這個。

## Quiz

**Q1.** 一個 AI agent 在處理 email 時，編造了不存在的訂單編號。這是哪個限制造成的？

- A) Context window 太小
- B) 沒有持久記憶
- C) 沒有世界模型（hallucination）
- D) 無法自我驗證

<details><summary>答案</summary>C。模型沒有等真實資料回來，直接預測了「最可能的參數值」。它不知道自己在瞎編，因為它的目標是產出統計上合理的下一個 token。</details>

**Q2.** 情境題：你把一份 200 頁的合約和三份無關的會議記錄一起丟給 LLM，問它合約的關鍵條款。LLM 的回答品質可能因為什麼下降？（複選）

- A) 合約太長，超過 context window
- B) 會議記錄是 noise，稀釋了 attention
- C) LLM 不懂法律
- D) LLM 沒有持久記憶

<details><summary>答案</summary>A、B。200 頁可能超過 context window（限制 2），即使沒超過，無關的會議記錄也會作為 noise 稀釋模型的注意力（限制 2 的另一面）。LLM 不是「不懂法律」，訓練資料中有大量法律文件，它在法律文字的 pattern matching 上其實不差。記憶問題跟這個情境無關，所有資料都已經在同一個 context 裡了。</details>

**Q3.** 以下哪個問題 LLM 最容易答錯？

- A) 把這段英文翻譯成中文
- B) 這家公司上季的營收是多少
- C) 幫我把這段 JSON 轉成 CSV
- D) 幫我摘要這篇文章

<details><summary>答案</summary>B。營收是需要查證的即時事實，LLM 的訓練資料不會有最新的數字，而且它無法自己去查。翻譯、格式轉換、摘要都是 pattern 很強的任務。</details>
