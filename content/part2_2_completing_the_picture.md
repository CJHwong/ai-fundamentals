# 2.2 Agent 如何補完 LLM 的限制

## 不是修補，是完成

Part 1 我們談了 LLM 的四個根本限制。Agent 架構裡的每個元素，剛好對應其中一個限制。這不是巧合，這就是 Agent 存在的理由。

## Memory → 跨越 Context 的連續性

LLM 每次推理都是獨立的，對話結束就忘記一切。就像一個每天早上醒來就失憶的人，不管昨天跟你聊了什麼、做了什麼決定，今天都要重新來過。

Agent 透過外部的 memory 系統解決這個問題。概念很簡單：既然 LLM 自己記不住，就把重要的事情寫在「筆記本」上，下次需要的時候再翻開來看。

具體來說：

- **對話結束前，把重要結論寫下來**（存到檔案或資料庫）
- **下次對話開始時，先把筆記載入 context**（讓 LLM 看到之前的紀錄）
- **隨著互動越來越多，筆記越來越豐富**（Agent 對你、對任務的「理解」持續累積）

這跟你用便利貼提醒自己明天要做的事是一樣的道理。LLM 的「大腦」不會記住，但它的「筆記本」會。

> 舉例：一個客服 Agent 在第一次對話中得知客戶 A 偏好用 email 而不是電話溝通。它把這件事寫進 memory。下次客戶 A 再來詢問，Agent 讀取 memory 後就知道不需要問溝通偏好，直接用 email 回覆。客戶感覺到「它記得我」，但其實只是筆記寫得好。

## Tools → 接上真實世界

LLM 的輸出只有文字。但透過 Tool Use，LLM 的文字輸出可以變成對外部系統的操作。

Tool Use 的核心其實很簡單：LLM 被訓練成能穩定輸出結構化的格式（通常是 JSON），這個 JSON 就是呼叫外部 API 的參數。LLM 不是真的在「操作」系統，它是在「描述」要做什麼操作，然後由程式去執行。

這解決了兩個限制：

- **Hallucination**：不再靠猜，而是透過 API 查詢真實資料（這就是 RAG 的概念）
- **無法驗證**：Agent 可以呼叫工具去檢查自己的輸出是否正確（例如執行程式碼看是否會報錯）

> 舉例：當 Agent 需要知道一筆訂單的狀態，它不是憑訓練資料去猜，而是呼叫 API 去查。拿到真實資料後再做判斷。Ground truth 來自系統，不來自模型。

### 順帶一提：Fine-tuning

另一種讓 LLM 獲得特定能力的方式是 **fine-tuning**：拿你自己的資料對模型做進一步訓練，直接改變模型內部的參數。

跟 RAG 的差別：RAG 是在 context 裡塞資料讓模型「看到」，fine-tuning 是把知識「烙進」模型裡。

聽起來很強，但代價不小：

- **成本高**：需要準備大量高品質的訓練資料，訓練過程也燒錢
- **風險大**：研究顯示 fine-tuning 可能破壞模型原本的安全對齊（safety alignment collapse），即使訓練資料本身沒問題
- **不好更新**：知識變了就要重新訓練，不像 RAG 改資料就好

所以除非你有很明確的「行為改變」需求（例如讓模型用特定格式輸出、學會一種特殊語氣），通常先用 RAG + Context Engineering 就夠了。這也是這份指南一直在強調的方向：先用 context 解決問題，能不動模型就不動。

## Loop → 透過驗證自我修正

One-shot 的 LLM 呼叫，錯了就是錯了，沒有第二次機會。

Agent 的 Plan-Act-Reflect 循環讓它可以：

1. 執行一個動作
2. 觀察結果
3. 判斷是否符合預期
4. 如果不對，調整策略再試

這等於給了 LLM 一個它原本不具備的能力：**自我修正**。

靠的是架構，不是更聰明的模型。一個 80% 準確率的 LLM，放進有驗證機制的循環裡，整體系統的可靠度可以遠超 80%。

> 實際應用：Claude Code 在寫完程式碼後會自動執行測試。如果測試失敗，它會讀錯誤訊息、分析原因、修改程式碼、再次測試。這個循環可能跑好幾輪，直到測試通過。

## 對照表

| LLM 的限制 | Agent 的對應元素 | 怎麼解決的 |
|-----------|-----------------|-----------|
| 沒有世界模型 (Hallucination) | Tools (RAG, API) | 從真實系統取得 ground truth |
| 有限的 Context | Memory | 把重要資訊持久化，需要時載入 |
| 沒有記憶 | Memory | 跨對話保持連續性 |
| 無法自我驗證 | Loop + Tools | 執行後觀察結果，失敗就調整重試 |

Agent 不是比較厲害的 LLM。它是一套用 LLM 當決策核心的系統架構。LLM 負責想，其他元件負責記、做、驗。

## Quiz

**Q1.** 配對題：LLM 的哪個限制，對應到 Agent 的哪個元素？

| LLM 的限制 | Agent 的元素 |
|-----------|------------|
| 1. Hallucination | a. Loop + Tools |
| 2. 沒有記憶 | b. Tools (RAG, API) |
| 3. 無法自我驗證 | c. Memory |

<details><summary>答案</summary>1-b、2-c、3-a。Hallucination 靠 Tools 查真實資料解決；沒有記憶靠 Memory 把重要事情寫下來；無法驗證靠 Loop + Tools 執行後檢查結果。</details>

**Q2.** 一個客服 Agent 記得客戶 A 偏好用 email 溝通。這個「記得」是怎麼做到的？

- A) 模型本身學會了客戶 A 的偏好
- B) 上次對話時把偏好寫進外部儲存，這次載入 context
- C) 每次都重新問客戶
- D) 工程師把客戶偏好寫在程式碼裡

<details><summary>答案</summary>B。LLM 本身不會記住任何事。Memory 的做法是把重要資訊寫到外部（檔案、資料庫），下次對話開始時載入 context 讓 LLM 看到。</details>
